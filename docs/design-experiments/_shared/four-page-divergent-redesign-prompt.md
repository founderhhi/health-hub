# Four-Page Divergent Redesign Prompt

Use this prompt for the next exploratory design round.

```text
This is a new round of design exploration for Health Hub.

The screenshots for the current state are available in:
/Users/anuraaggudimella/Documents/health-hub/docs/design-experiments/current

Use every relevant screenshot in that folder as current-state evidence.
Do not assume a single screenshot tells the whole story.

You are designing for 4 pages only:
1. Landing page
2. Patient dashboard
3. GP dashboard
4. Specialist dashboard

Important framing:
- This is not a “slightly refine the current UI” exercise.
- This is also not a “be random for the sake of diversity” exercise.
- I want meaningful variation that stays grounded in the purpose of each page and in the Health Hub brand.
- Use the current product as a functional and contextual reference.
- Do not let the current visuals limit the range of ideas.

Brand truths that still matter:
- Health Hub should feel trustworthy, human, supportive, and healthcare-credible.
- The product should feel warm and confident, not cold, sterile, or generic SaaS.
- It can become more premium, more modern, more editorial, more operational, or more guided depending on the page.
- Every page should make the next step clearer than it is today.
- The final output should still feel believable for a healthcare platform, not like an unrelated consumer app.

Core instruction:
Create materially different design directions, but make the differences purposeful.
The point is to explore different design choices for the actual needs of each page, not just to change colors or decoration.

Use the screenshots, the page purpose, and the likely user mindset to define each direction.

For every page:
- first explain what the page is for
- explain what the user most likely needs on that page
- explain what is visually not working well enough in the current state
- then generate multiple redesign directions that solve that page’s specific problem in different ways

Page briefs

1. Landing page
What this page is:
- The first impression of Health Hub.
- It introduces the platform, explains the value, and gets the user into the right entry point.

User mindset:
- “Can I trust this?”
- “What exactly does this platform help me do?”
- “Am I a patient or provider entering here?”
- “Why should I take action now?”

Current design problem to solve:
- The landing page may explain too much with one visual rhythm.
- The page needs stronger hierarchy between trust, value proposition, primary action, and ecosystem breadth.
- The first screen should do more work.

Create 4 landing page directions:
- Direction A: high-conversion care entry
- Direction B: ecosystem explainer with clearer service grouping
- Direction C: premium trust-led healthcare brand
- Direction D: more modern, product-forward digital health brand

2. Patient dashboard
What this page is:
- The patient’s operational home.
- It should help the patient understand current status, next steps, care options, records, and ongoing actions.

User mindset:
- “What do I need to do now?”
- “Where is my care journey right now?”
- “How do I continue consultation, records, pharmacy, diagnostics, or follow-up?”
- “What matters most on this screen?”

Current design problem to solve:
- The dashboard may currently emphasize service breadth more than guided care.
- Too many modules may feel similar in weight.
- The page should feel more intentional about status, next step, and primary action.

Create 4 patient dashboard directions:
- Direction A: guided care-plan home
- Direction B: fast utility super-app home
- Direction C: premium concierge care home
- Direction D: calmer wellness-and-recovery-oriented home

3. GP dashboard
What this page is:
- The general practitioner’s command center.
- It should help a GP move through patients, urgency, tasks, notes, and actions efficiently.

User mindset:
- “Who needs my attention first?”
- “What is urgent?”
- “What action can I complete quickly?”
- “How do I keep throughput high without losing clarity?”

Current design problem to solve:
- The GP page should feel operationally sharp without becoming chaotic.
- Queue, urgency, and task clarity should be stronger than decorative polish.
- It should feel professional and efficient, but still aligned to the Health Hub brand.

Create 4 GP dashboard directions:
- Direction A: high-throughput clinical operations
- Direction B: calmer doctor workspace
- Direction C: decision-first triage board
- Direction D: premium practitioner cockpit

4. Specialist dashboard
What this page is:
- A deeper clinical workspace for focused specialty care.
- It should support case depth, referrals, review, interpretation, and ongoing patient context.

User mindset:
- “What case context do I need immediately?”
- “What is complex, pending, or escalated?”
- “How do I move from referral to expert action smoothly?”
- “What deserves focus versus secondary information?”

Current design problem to solve:
- The specialist page should feel more focused and case-oriented than a generic dashboard.
- It should visually communicate depth, context, and confidence.
- It must support concentration rather than just scanning.

Create 4 specialist dashboard directions:
- Direction A: deep-case review workspace
- Direction B: elegant specialist consult desk
- Direction C: evidence-and-referral command center
- Direction D: calm expert workspace with stronger focus hierarchy

Variation rules

For each page:
- Create exactly 4 directions.
- The 4 directions must feel meaningfully different in hierarchy, density, tone, and composition.
- Do not make 4 variants that are basically the same design with different styling.

Across all directions:
- Use different layout models where appropriate
- Use different typography character where appropriate
- Use different spacing rhythm and density
- Use different ways of handling cards, grouping, and emphasis
- Use different primary-action strategies
- Use different emotional tones

Still, keep these non-negotiables:
- believable healthcare product
- brand trust
- user clarity
- functional comprehension

Output requirements

For each of the 4 pages:
- 1 short page explanation
- 1 short diagnosis of the current visual issue
- 4 actual rendered redesign concepts
- 1 comparison summary explaining how the 4 directions differ
- 1 recommendation for which 2 directions are worth taking forward

Total required rendered concepts:
- 16 renders minimum

Final deliverables:
- separate renders for all 16 directions
- one overview board per page
- one global comparison board across all 4 pages
- a short written rationale for each direction

Important self-check:
Within each page family, ask:
“Would a stakeholder immediately understand why these 4 directions are different, and what design choice each one is exploring?”

If not, push the differences further.

Do not default to safe sameness.
Do not default to arbitrary novelty.
Explore meaningful alternatives for the actual job each page has to do.
```
